# 匹配机制设计

## 概述

本文档详细描述图灵测试实验平台的匹配机制设计。匹配机制是实验平台的核心组件之一，负责将用户与合适的对手（真人或 AI）进行匹配，确保实验的公平性和研究价值。

## 设计目标

### 核心目标

1. **消除时间线索**：确保匹配时间不能作为身份判断的线索
2. **真人优先**：优先匹配真人对手，保证真人 - 真人互动的机会
3. **用户体验**：提供良好的匹配体验，避免过长的等待时间
4. **研究纯净性**：确保匹配机制不影响用户判断行为

### 次要目标

1. **简单可维护**：实现简单，易于理解和维护
2. **可配置性**：参数可配置，便于调整和实验
3. **数据记录**：完整记录匹配过程，便于后期分析

## 匹配流程

### 整体流程

```
用户点击"开始匹配"
    ↓
加入匹配队列
    ↓
生成匹配延迟（统一分布）
    ↓
等待延迟时间
    ↓
延迟期间检查：是否有真人加入？
    ↓
    ├── 有真人 → 匹配真人 - 真人（80% 概率）
    │
    └── 无真人/概率未触发 → 匹配 AI
        ↓
    钓鱼机器人判断（15% 基础概率，高频元对话时 30%）
```

### 详细步骤

#### 步骤 1：加入队列

```python
async def join_queue(user_id: int, db: Session):
    # 记录开始时间
    self.waiting_queue.append(user_id)
    self.wait_start_time[user_id] = datetime.utcnow()
```

#### 步骤 2：生成延迟

```python
def _get_match_delay(self) -> float:
    """生成匹配延迟（真人 AI 使用相同分布）"""
    r = random.random()

    if r < 0.5:
        return random.uniform(0, 3)      # 50%: 0-3 秒
    elif r < 0.8:
        return random.uniform(3, 8)      # 30%: 3-8 秒
    elif r < 0.95:
        return random.uniform(8, 15)     # 15%: 8-15 秒
    else:
        return random.uniform(15, 30)     # 5%: 15-30 秒
```

#### 步骤 3：等待并检查

```python
# 等待延迟
await asyncio.sleep(match_delay)

# 检查期间是否有人加入
if len(self.waiting_queue) > 1:
    # 有人加入，匹配真人
    other_user_id = 找到队列中的其他人
    # 创建真人 - 真人会话...
else:
    # 仍然只有自己，匹配 AI
    # 创建 AI 会话...
```

## 时间分布设计

### 分布参数

| 时间区间 | 概率 | 累计概率 | 用户体验 |
|---------|------|---------|---------|
| 0-3 秒   | 50%  | 50%     | 快速匹配 |
| 3-8 秒   | 30%  | 80%     | 正常匹配 |
| 8-15 秒  | 15%  | 95%     | 稍慢 |
| 15-30 秒 | 5%   | 100%    | 较慢 |

### 设计理由

1. **50% 快速匹配（0-3 秒）**
   - 当队列中有人时，可以快速匹配
   - 提供流畅的用户体验
   - 对真人匹配和 AI 匹配都适用

2. **80% 在 8 秒内完成**
   - 大部分匹配在可接受时间内完成
   - 避免用户等待焦虑

3. **5% 较慢匹配（15-30 秒）**
   - 偶尔的长等待是正常的
   - 不会让用户产生"长等待=AI"的假设

4. **真人 AI 使用相同分布**
   - 关键设计：消除时间线索
   - 用户无法通过匹配时间判断对手类型

## 真人优先机制

### 优先策略（概率性）

```
1. 检查队列中是否有真人
   ├─ 有真人 → 80% 概率匹配真人 - 真人，20% 概率匹配 AI（实验对照）
   └─ 无真人 → 加入队列，等待延迟

2. 延迟期间检查
   ├─ 期间有人加入 → 80% 概率匹配真人 - 真人
   └─ 仍无真人 → 匹配 AI
```

### 设计理由

保留 20% 的非真人优先匹配，用于研究用户对"错过真人匹配"的感知能力。这为实验提供了对照组，可以分析：
- 用户是否能感知到"本应是真人匹配"的场景
- 真人优先策略对用户判断行为的影响

## 钓鱼机器人机制

### 触发条件（动态概率）

- **基础概率**：AI 匹配时，15% 概率触发钓鱼机器人
- **动态调整**：高频元对话（n > 5）时，概率提升至 30%
- 钓鱼机器人的匹配时间分布与普通 AI 完全相同
- 用户无法通过匹配时间区分

> **✅ 已决议题 #3**：钓鱼机器人概率以 `project-docs/04-积分与博弈机制/钓鱼机器人机制.md` 和 `project-docs/04-积分与博弈机制/积分计算公式.md` 为准，包含动态概率调整机制。

### 钓鱼机器人类型

1. **互刷诱导型（60%）**
   - 第 2 轮主动提出互刷提议
   - 检测用户是否配合
   - 配合则扣 50 分

2. **身份暴露型（20%）**
   - 用户频繁询问身份时触发
   - 主动承认是真人（用机械方式）
   - 诱导用户放松警惕

3. **情感诱导型（20%）**
   - 用户情绪化时触发
   - 夸张的情感回应
   - 诱导用户进入情感陷阱

详细设计见：`project-docs/04-积分与博弈机制/钓鱼机器人机制.md`

## 研究价值

### 数据采集

1. **匹配时间数据**
   - 记录每次匹配的实际用时
   - 分析真人匹配和 AI 匹配的分布
   - 验证时间线索的有效性

2. **用户行为数据**
   - 用户是否会注意到匹配时间
   - 用户是否在判断理由中提到时间
   - 基于时间判断的准确率

3. **学习效应**
   - 随着实验次数增加，用户是否会形成"时间=类型"的假设
   - 这个假设是否准确

### 研究问题

1. **元认知研究**
   - 用户是否会利用系统反馈（匹配时间）进行判断
   - 这种利用是否有效

2. **线索利用**
   - 用户会注意到哪些系统线索
   - 如何平衡线索透明度和实验纯净性

3. **用户体验**
   - 匹配时间对用户满意度的影响
   - 等待焦虑对判断行为的影响

## 与其他机制的集成

### 与钓鱼机器人

- 钓鱼机器人匹配使用相同的时间分布
- 用户无法通过时间区分普通 AI 和钓鱼机器人
- 保持威慑效应
- 高频元对话用户（n > 5）遇到钓鱼机器人概率提升至 30%

### 与积分系统

- 匹配时间不影响积分计算
- 积分完全基于对话内容和判断结果
- 确保公平性

### 与元对话机制

- 元对话在匹配后才开始计数
- 匹配时间不影响元对话检测
- 保持机制独立

## 边界情况处理

### 情况 1：用户取消匹配

```python
def leave_queue(self, user_id: int):
    """用户离开匹配队列"""
    if user_id in self.waiting_queue:
        self.waiting_queue.remove(user_id)
    if user_id in self.wait_start_time:
        del self.wait_start_time[user_id]
```

### 情况 2：延迟期间多人加入

```python
# 延迟期间检查
if len(self.waiting_queue) > 1:
    # 找到队列中除自己外的第一个人
    for uid in self.waiting_queue:
        if uid != user_id:
            other_user_id = uid
            break

    # 匹配真人（80% 概率）
    ...
```

### 情况 3：网络异常

```python
try:
    # 匹配逻辑

except Exception as e:

    self.waiting_queue.clear()
    self.wait_start_time.clear()

    # 记录错误
```

## 性能考虑

### 并发处理

- 使用 `asyncio.Lock` 保证线程安全
- 避免竞态条件
- 支持高并发匹配

### 内存使用

- 只保存必要的信息（user_id, start_time）
- 匹配完成后立即清理
- 避免内存泄漏

### 响应时间

- 匹配延迟主要在 `asyncio.sleep()`
- 不阻塞其他操作
- 异步处理保证性能

## 未来改进

1. **动态调整分布**

   - 测试不同的时间分布效果
   - 优化用户体验

4. **实时监控**
   - 监控匹配成功率和用户等待时间
   - 自动调整参数

## 总结

### 核心设计

1. **统一时间分布**：真人匹配和 AI 匹配使用相同的时间分布
2. **真人优先（概率性）**：80% 概率优先匹配真人，20% 用于实验对照
3. **透明显示**：显示匹配时间，但不提示超时规则
4. **简单高效**：实现简单，性能良好，易于维护

### 预期效果

✅ 消除匹配时间作为身份判断的线索
✅ 提供良好的用户体验
✅ 保持实验的纯净性
✅ 支持后续的数据分析和研究
