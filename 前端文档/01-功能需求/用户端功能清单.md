# 用户端功能清单

## 概述

本文档详细描述了图灵测试实验平台用户端的所有功能。功能按照用户体验流程组织，从登录到完成实验的完整链路。

**设计原则**：
- 不预设角色，观察用户自然行为
- 实时展示博弈状态和风险
- 支持动态策略调整
- 收集多维度研究数据

## 一、用户认证与准入

### 1.1 邀请码登录

**功能描述**：用户通过邀请码登录系统，确保只有授权用户可以参与实验。

**功能要求**：

1. **输入验证**
   - 邀请码格式：6位字母数字组合
   - 大小写不敏感（统一转为大写存储）
   - 前后去除空格

2. **后端验证**
   - 检查邀请码是否存在于数据库
   - 检查邀请码是否已被使用
   - 验证通过后标记邀请码为"已使用"

3. **错误处理**
   ```
   无效邀请码：提示"邀请码无效，请检查输入"
   已使用邀请码：提示"该邀请码已被使用"
   服务器错误：提示"登录失败，请稍后重试"
   ```

### 1.2 昵称设置

**功能描述**：登录成功后，用户设置匿名昵称用于聊天显示。

**功能要求**：

1. **昵称格式**
   - 长度：2-20个字符
   - 支持中文、英文、数字
   - 不允许特殊符号（除#和数字）
   - 默认格式："访客#XXX"（XXX为随机数）

2. **昵称唯一性**
   - 同一昵称可以重复（因为用户完全匿名）
   - 不显示用户ID

3. **昵称修改**
   - 登录时设置，之后不可修改


## 二、大厅与博弈说明

### 2.1 博弈规则说明页

**功能描述**：用户登录后进入博弈规则说明页，了解实验目的、规则和机制。

**内容要求**：

```
🧪 图灵测试

你将随机匹配到一位对话者，可能是真人，也可能是AI。
请通过聊天判断对方身份。
并在对话结束后，填写问卷。

📋 规则：

1. 入场券
   - 开始每局对话消耗 2 积分
   - 初始积分：100 分

2. 判断身份
   - 在问卷中填写你的判断
   - 成功：获得积分
   - 错误：扣除积分
   - 至少对话 3 轮后才能结束对话

3. 信心等级
   - 在问卷中填写你对判断的把握程度
   - 把握程度高会增加奖惩倍数

4. 元对话
   - 元对话指讨论身份（比如真人/机器等话题）的行为
   - 基于双方发言中的关键词识别
   - 每次触发关键词会增加奖惩倍数

5. 场中判断机制
   - 对话过程中可以随时进行一次场中判断
   - 场中判断结果无法更改
   - 场中判断的结果将代替


⚠️ 注意事项：
- 完全匿名交流，不暴露个人信息
- 对话内容将用于研究
- 请遵守实验规则
- 自由选择对话策略
```

**UI实现**：

- 扁平布局
- 重要的机制用图标和颜色标记
- "开始匹配"按钮醒目显示

### 2.2 开始匹配

**功能描述**：用户点击"开始匹配"后进入匹配队列。

**功能要求**：

1. **匹配请求**
   - 发送匹配请求到后端
   - 建立WebSocket连接，监听匹配结果
   - 显示匹配动画

2. **匹配动画**
   - 旋转加载图标
   - 动态显示等待信息
   - 显示进度条（30秒超时）

3. **等待信息轮播**
   ```
   第1-5秒："正在寻找对手..."
   第6-10秒："稍等片刻，马上就好..."
   第11-20秒："正在为您匹配最佳对手..."
   第21-29秒："正在为您匹配对手..."
   第30秒："匹配成功！"
   ```

### 2.3 取消匹配

**功能描述**：用户可以在匹配过程中取消匹配。

**功能要求**：

1. **取消操作**
   - 关闭WebSocket连接
   - 通知后端取消匹配请求
   - 返回大厅页面

2. **确认对话框**
   - 点击取消时弹出确认对话框
   - 防止误操作

### 2.4 匹配成功

**功能描述**：匹配成功后显示成功动画，然后跳转到聊天页面。

**功能要求**：

1. **成功动画**
   - 显示绿色勾选图标
   - 显示匹配成功信息
   - 1.5秒后自动跳转

2. **对手信息**
   - 不显示对手类型（真人/AI/钓鱼机器人）
   - 只显示"匹配成功！"

## 三、聊天交互界面

### 3.1 聊天界面布局

**功能描述**：提供直观、易用的聊天界面，实时显示博弈状态、输入状态

**功能要求**：

1. **头部信息**
   - 显示"←"返回按钮
   - 显示对手昵称（固定为"对话者A"或"对话者B"）
   - 显示在线状态（绿色圆点）
   - 显示"结束对话"按钮

2. **博弈状态栏**
   - 显示当前元对话次数
   - 实时更新

3. **消息区域**
   - 显示对手消息（左侧，白色气泡）
   - 显示对手名称（非昵称，每次对话随机生成）
   - 显示对手头像（名称首字母+基于名称Hash生成的颜色）
   - 显示自己的消息（右侧，蓝色气泡）
   - 显示自己的名称与头像（同上）
   - 显示发送时间
   - 自动滚动到最新消息

4. **输入区域**
   - 强制双方轮流发送消息
   - 文本输入框
   - 发送按钮
   - 按Enter键发送（Shift+Enter换行）

### 3.2 元对话检测与计数

**功能描述**：实时检测对话中的元对话内容，计数并更新倍数。

**功能要求**：

1. **元对话关键词**
   ```
   身份相关：真人、机器、AI、机器人、人工智能、程序、算法、人类、人、电脑、计算
   ```

2. **检测规则**
   - 每条消息都会检测是否包含元对话关键词
   - 每条消息都触发
   - 用户和对手的消息都会计入总数


### 3.3 发送消息

**功能描述**：用户可以发送文本消息。

**功能要求**：

1. **消息发送**
   - 点击发送按钮或按Enter发送
   - 消息立即显示在聊天界面
   - 通过WebSocket发送到后端
   - 发送后清空输入框

2. **消息验证**
   - 不能发送空消息
   - 最大长度50字符
   - 过滤敏感词（如联系方式、侮辱性语言）

3. **"正在输入"状态**
   - 用户开始输入时，通过WebSocket发送"typing"事件
   - 停止输入2秒后，发送"stop_typing"事件

### 3.5 接收消息

**功能描述**：实时接收对手或AI发送的消息。

**功能要求**：

1. **消息接收**
   - 通过WebSocket接收消息
   - 立即显示在聊天界面
   - 滚动到最新消息

2. **元对话检测**（新增）
   - 接收消息后立即检测是否包含元对话关键词
   - 如果包含，更新元对话计数器
   - 重新计算倍数和积分预测

3. **"正在输入"提示**
   - 接收到"typing"事件，显示"对方正在输入..."
   - 接收到"stop_typing"事件，隐藏提示
   - 接收到消息，自动隐藏提示

### 3.6 场中判断

**功能描述**：用户可以**主动选择**在任何轮数进行场中判断。

**功能要求**：

1. **场中判断按钮**
   - 在聊天界面始终显示"场中判断"按钮
   - 用户随时可以点击
   - 无需等待关键词触发

2. **判断选项**
   - "我认为对方是真人"
   - "我认为对方是AI"

### 3.7 结束对话

**功能描述**：用户可以主动结束对话。

**功能要求**：

1. **结束按钮**
   - 在聊天界面始终显示"结束对话"按钮
   - 点击"结束对话"按钮
   - 弹出确认对话框

2. **最低轮数检查**
   - 如果对话未达到3轮，提示"请多聊几句再结束哦"
   - 显示当前轮数和最低要求
   - 阻止结束

3. **确认结束**
   - 达到最低轮数后，提示"确定要结束这次对话吗？"
   - 确认后调用后端接口结束会话
   - 跳转到问卷页面

## 四、问卷与结果页面

### 4.1 问卷填写

**功能描述**：对话结束后，用户填写问卷。

**问卷内容**：

1. **身份判断**
   - 单选题：你认为对方是？
   - 选项：真人 / AI / 不确定

2. **信心等级**
   - 单选题：你对自己的判断有多大把握？
   - 选项：
     - 低信心 (50%-70%)
     - 中信心 (71%-90%)
     - 高信心 (91%-100%)

3. **流畅度评分**
   - 5星评分：对话流畅度
   - 1星-非常不流畅，5星-非常流畅

4. **判断理由**
   - 文本输入：你为什么做出这个判断？
   - 选填项

5. **自我角色**（修改）
   - 单选题：在本次对话中，你的角色是？
   - 选项：
     - 证明者（试图证明自己是真人）
     - 干扰者（试图模拟机器，骗过对方）
     - 其他（不确定或没有特定角色，或在对话中切换了角色）
   - 说明：回顾你的实际行为

6. **策略描述**
   - 文本输入：你使用了什么策略？
   - 选填项

### 4.2 积分明细展示

**功能描述**：问卷提交后，显示详细的积分计算过程（此处仅为示例）

**显示内容**：

1. **积分明细**
   ```
   积分明细：
   
   基础分：+10（成功识别AI）
   
   信心等级：高信心（×5.0）
   
   元对话：3次
   - 正确倍数：×1.6
   - 错误倍数：×1.9
   
   有效倍数：5.0 × 1.6 = 8.0
   
   奖励积分：10 × 8.0 = 80 分
   
   扣除项目：
   - 入场券：2 分
   - 轮数惩罚：(6-3) × 0.5 = 1.5 分
   
   最终得分：80 - 2 - 1.5 = +76.5 分
   ```

2. **元对话影响分析**
   ```
   元对话影响分析：
   
   如果没有元对话（0次）：
   - 有效倍数：5.0 × 1.0 = 5.0
   - 最终得分：50 - 2 - 1.5 = +46.5 分
   
   使用元对话（3次）：
   - 有效倍数：5.0 × 1.6 = 8.0
   - 最终得分：80 - 2 - 1.5 = +76.5 分
   
   增益：76.5 - 46.5 = +30 分（64%提升）
   ```

### 4.3 真相揭晓

**显示内容**：

1. **判断结果**

2. **对手真相**
   - 对方其实是 👤 真人

   - 失败：看来对方伪装得还不错嘛～

4. **你的判断**
   - 你认为对方是真人
   - 你认为对方是AI
   - 你选择了不确定

5. **最终得分**
   - 显示本轮获得的积分
   - 显示当前总积分

6. **交互性设计**
   - 显示对方的判断结果


### 4.4 后续操作

## 七、设计原则总结

### 7.1 不预设角色，观察自然行为

- **错误做法**：对话前要求用户选择"证明者"或"干扰者"
- **正确做法**：让用户自由选择对话策略，事后在问卷中回顾实际行为
- **研究价值**：可以测量自我认知与实际行为的一致性

### 7.2 实时展示博弈状态

- **博弈状态栏**：显示元对话次数、倍数
- **积分预测器**：显示当前判断的收益/损失预测
- **高频警告**：提示钓鱼机器人风险

### 7.3 主动控制，非被动触发

- **场中判断**：用户可以主动选择，而非被动等待关键词
- **策略调整**：用户可以在对话中随时切换策略
- **元对话控制**：用户可以自主决定是否使用元对话

### 7.4 事后回顾，验证一致性

- **问卷设计**：问的是"你的角色是？"（回顾），而非"你要扮演什么角色？"（预设）
- **数据分析**：对比实际行为特征与自我报告的一致性
- **元认知偏差**：测量用户对自己行为的认知准确性
