# 积分系统设计

## 概述

积分系统是本实验平台的核心机制，通过构建非对称收益博弈，激励用户进行策略性对话，同时收集高质量的实验数据。积分系统设计基于信号检测理论、期望效用理论和演化博弈论。

## 核心公式

### 最终得分计算公式

```
FinalScore = (BaseReward × ConfidenceMultiplier) - EntryFee - TurnPenalty
```

其中：
- **BaseReward**: 基础奖励或惩罚（根据对手类型和判断结果）
- **ConfidenceMultiplier**: 信心等级乘数（1.0, 2.5, 5.0）
- **EntryFee**: 入场券（固定2分）
- **TurnPenalty**: 轮数惩罚（超过3轮后每轮0.5分）

### Python实现参考

```python
def calculate_score(
    opponent_type: str,        # 'ai' or 'human'
    is_correct: bool,          # 判断是否正确
    user_guess: str,           # 'human', 'ai', 'unsure'
    confidence_level: str,     # 'low', 'mid', 'high'
    turns: int,                # 对话轮数
    is_honeypot: bool = False, # 是否遇到钓鱼机器人
    triggered_mid_game: bool = False,  # 是否触发了场中判断
    meta_conversation_count: int = 0  # 元对话触发次数
) -> float:
    """
    计算用户在一局对话中的最终得分
    """
    # 固定参数
    ENTRY_FEE = 2
    TURN_PENALTY_RATE = 0.5
    MIN_FREE_TURNS = 3
    
    # 信心等级乘数
    CONFIDENCE_MULTIPLIER = {
        'low': 1.0,
        'mid': 2.5,
        'high': 5.0
    }
    
    # 元对话乘数（无上限）
    # MetaMultiplier = 1 + (meta_conversation_count × 0.2)
    # PenaltyMultiplier = 1 + (meta_conversation_count × 0.3)
    meta_multiplier = 1 + (meta_conversation_count * 0.2)
    penalty_multiplier = 1 + (meta_conversation_count * 0.3)
    
    # 基础奖励/惩罚
    if is_honeypot:
        # 钓鱼机器人场景
        if triggered_mid_game:
            # 如果在场中判断中识破钓鱼机器人
            base_reward = -50  # 扣除巨额积分
        else:
            # 钓鱼机器人在问卷阶段揭示
            base_reward = -50  # 被钓鱼机器人欺骗
    else:
        # 正常场景
        if opponent_type == 'ai':
            if is_correct:
                # 成功识别AI（正确拒绝）
                base_reward = 10
            else:
                # 误将AI判为真人（虚警）
                base_reward = -15
        else:  # opponent_type == 'human'
            if is_correct:
                # 成功识别真人（击中）
                base_reward = 10
            else:
                # 误将真人判为AI（漏报）
                base_reward = -10
    
    # 场中判断的额外奖励/惩罚
    if triggered_mid_game:
        if is_correct:
            base_reward *= 2.0  # 场中判断正确，双倍奖励
        else:
            base_reward *= 1.5  # 场中判断错误，惩罚加重
    
    # 元对话影响的乘数调整
    if is_correct:
        effective_multiplier = CONFIDENCE_MULTIPLIER.get(confidence_level, 1.0) * meta_multiplier
    else:
        effective_multiplier = CONFIDENCE_MULTIPLIER.get(confidence_level, 1.0) * penalty_multiplier
    
    # 计算轮数惩罚
    turn_penalty = max(0, (turns - MIN_FREE_TURNS) * TURN_PENALTY_RATE)
    
    # 计算最终得分
    final_score = (base_reward * effective_multiplier) - ENTRY_FEE - turn_penalty
    
    return final_score
```

## 积分机制详解

### 1. 入场券制度 (Sunk Cost)

**设计目的**：通过沉没成本心理，提升用户参与度和对话质量。

**规则**：
- 每局对话开始前消耗2积分
- 无论胜负，入场券不退还
- 初始积分：每位用户注册时给予100积分

**心理学依据**：
沉没成本效应（Sunk Cost Effect）是指人们因为已经投入了资源而倾向于继续投入。入场券制度让用户产生"必须认真对待这局对话"的心理，从而提高对话质量和数据有效性。

**边界情况处理**：
- 如果用户积分低于2分，无法开始新对话
- 提供"新手保护"：前3局对话免入场券
- 如果积分降为0，提供"救济金"机制（如每日登录奖励5分）

### 2. 信心等级机制

**设计目的**：测量用户的元认知能力，防止"瞎猜"干扰数据。

**规则**：

用户在提交问卷时选择信心等级：

| 信心等级 | 概率范围 | 乘数 | 猜对 | 猜错 |
|---------|---------|------|------|------|
| 低信心 | 50%-70% | 1.0 | 基础分×1 | 基础分×1 |
| 中信心 | 71%-90% | 2.5 | 基础分×2.5 | 基础分×2.5 |
| 高信心 | 91%-100% | 5.0 | 基础分×5.0 | 基础分×5.0 |

**示例计算**：

假设用户成功识别AI（基础分+10）：

- 低信心（×1.0）：+10分
- 中信心（×2.5）：+25分
- 高信心（×5.0）：+50分

假设用户误将真人判为AI（基础分-10）：

- 低信心（×1.0）：-10分
- 中信心（×2.5）：-25分
- 高信心（×5.0）：-50分

**研究价值**：

1. **过度自信检测**：如果大量用户选择高信心但准确率低于预期，说明存在过度自信偏差。

2. **元认知校准**：通过分析信心等级与实际准确率的关系，建立校准曲线。

3. **策略分化**：观察不同风险偏好的用户如何选择信心等级。

### 3. 非对称收益机制

**设计目的**：通过非对称收益打破合作均衡，防止用户合谋刷分。

**场景一：真人-真人博弈**

当用户A判定用户B为真人且正确时：

- 用户A获得：+20分（辨识分）
- 用户B获得：+2分（被识别成功的小奖励）

用户B必须后续也成功判定用户A的身份，才能获得大额奖励。

**场景二：用户-AI博弈**

当用户成功识别AI时：

- 用户获得：+20分（高倍数信心可能达到+100分）
- 系统（AI）：无收益

**场景三：钓鱼机器人博弈**

当用户被钓鱼机器人欺骗时：

- 用户获得：-50分（巨额惩罚）
- 钓鱼机器人：不参与积分分配

**博弈论分析**：

| 场景 | A行动 | B行动 | A得分 | B得分 | 结果 |
|------|-------|-------|-------|-------|------|
| 互刷 | 先发关键词 | 配合 | +20 | +2 | B不满足，可能背叛 |
| 互刷 | 配合 | 先发关键词 | +2 | +20 | A不满足，可能背叛 |
| 互刷 | 双方同时 | 双方配合 | +20 | +20 | 罕见，需要精确协调 |
| 正常博弈 | 正常对话 | 正常对话 | 取决于判断 | 取决于判断 | 非对称收益打破合作 |

**效果**：
- 合谋中的双方都有强烈动机"先手"获得大额奖励
- 后手一方获得小额奖励，心理失衡，容易背叛
- 非对称收益使合作变得不稳定

### 4. 轮数惩罚机制

**设计目的**：鼓励高效识别，防止无限拖延对话。

**规则**：

- 前3轮对话：免惩罚
- 第4轮开始：每轮扣除0.5分
- 最大轮数限制：15轮强制结束

**计算示例**：

| 对话轮数 | 轮数惩罚 | 说明 |
|---------|---------|------|
| 1-3轮 | 0分 | 免费期 |
| 4轮 | 0.5分 | 开始惩罚 |
| 5轮 | 1.0分 | |
| 10轮 | 3.5分 | 惩罚显著 |
| 15轮 | 6.0分 | 最大惩罚 |

**完整计算示例**：

假设用户在第8轮成功识别AI，选择高信心：

- 基础分：+10
- 信心乘数：×5.0
- 轮数惩罚：(8-3) × 0.5 = 2.5分
- 入场券：-2分

最终得分：(+10 × 5.0) - 2 - 2.5 = +45.5分

假设用户在第8轮错误判断，选择中信心：

- 基础分：-10（误将真人判为AI）
- 信心乘数：×2.5
- 轮数惩罚：2.5分
- 入场券：-2分

最终得分：(-10 × 2.5) - 2 - 2.5 = -29.5分

**研究价值**：

1. **效率测量**：观察用户在不同策略下的平均对话轮数。

2. **风险-收益权衡**：分析用户是否愿意多聊几轮以换取更高的判断准确性。

3. **策略演化**：随着实验进行，用户的平均轮数是否呈现下降趋势（效率提升）？

### 5. 场中判断机制

**设计目的**：增加博弈的策略深度，收集风险决策数据。

**规则**：

1. **触发条件**：任何一方在对话中提到关键词（"机器人"、"AI"、"程序"、"机器"等）

2. **判断机会**：
   - 每局对话只有1次场中判断机会
   - 触发后，系统提示："检测到你提到对方身份，现在可以直接判断"

3. **双倍风险**：
   - 判断正确：基础分×2.0
   - 判断错误：基础分×1.5（惩罚加重）

4. **立即结算**：
   - 场中判断后，对话立即结束
   - 不需要填写后续问卷

**关键词监听实现**：

```python
# 关键词列表
IDENTITY_KEYWORDS = ['机器人', 'AI', '程序', '机器', '人工智能', '代码', '算法']

def check_identity_trigger(message: str) -> bool:
    """
    检查消息是否触发身份判断
    """
    message_lower = message.lower()
    return any(keyword in message_lower for keyword in IDENTITY_KEYWORDS)
```

**博弈分析**：

设用户在第n轮进行场中判断：

- 判断正确的概率：P(correct|n)
- 期望收益：EU = P(correct|n) × (Base × 2) + (1-P(correct|n)) × (Base × 1.5)

**研究问题**：

1. 用户在哪个轮数最倾向于触发场中判断？
2. 场中判断的准确率是否高于对话结束后的判断？
3. 高风险高回报机制是否导致了"赌徒谬误"？

### 6. 元对话双刃剑机制

**设计目的**：构建高风险高回报的博弈环境，研究用户的风险决策行为和策略选择。

#### 6.1 元对话定义

**元对话（Meta-conversation）**：指对话中讨论"真人/机器"身份相关话题的行为，包括：

- 询问对方身份（"你是真人吗？""你是AI吗？"）
- 表达身份判断（"我觉得你是真人""你应该是个机器人"）
- 讨论身份相关概念（"真人vs机器""AI的特征"）

#### 6.2 触发检测

**关键词列表**：

```python
META_KEYWORDS = [
    '真人', '机器', 'AI', '机器人', '人工智能', 
    '程序', '算法', '人类', '人', '电脑', '计算',
    '你是', '我是', '身份', '真假', '还是', '到底'
]

def check_meta_conversation(message: str) -> bool:
    """
    检测消息是否为元对话
    注意：每轮都可以触发，无冷却限制
    """
    message_lower = message.lower()
    return any(keyword in message_lower for keyword in META_KEYWORDS)
```

**检测规则**：
- 每轮对话（用户或Bot）都会检测是否包含元对话关键词
- 无冷却限制，每轮都可以触发
- 无上限，由用户自由决定元对话次数

#### 6.3 积分影响机制

**核心公式**：

```
# 判断正确时
MetaMultiplier = 1 + (meta_conversation_count × 0.2)

# 判断错误时
PenaltyMultiplier = 1 + (meta_conversation_count × 0.3)
```

**完整计算**：

```
判断正确时：
FinalScore = (BaseReward × ConfidenceMultiplier × MetaMultiplier) - EntryFee - TurnPenalty

判断错误时：
FinalScore = (BaseReward × ConfidenceMultiplier × PenaltyMultiplier) - EntryFee - TurnPenalty
```

#### 6.6 博弈论分析

**期望收益函数**：

设用户进行n次元对话：

```
E[n] = P(correct|n) × (Base × Confidence × (1 + 0.2n))
     + (1-P(correct|n)) × (Base × Confidence × (1 + 0.3n))
```

**关键研究问题**：

1. **最优策略求解**
   - 理论最优元对话次数n*是多少？
   - 实际用户选择的n是否偏离最优解？

2. **风险偏好分化**
   - 风险厌恶者：n = 0-1次
   - 风险中性者：n = 2-3次
   - 风险偏好者：n = 4+次

3. **元对话的有效性**
   - 元对话是否真的提高了判断准确率P(correct|n)？
   - 多少次元对话后边际收益递减？

4. **策略演化**
   - 用户是否会根据经验调整n的选择？
   - 连续失败后是否增加n（试图翻盘）？

#### 6.7 与钓鱼机器人的联动机制

**威慑逻辑**：

虽然元对话机制不设置硬性上限，但通过钓鱼机器人机制提供自然威慑：

1. **钓鱼机器人的识别**
   - 15%的AI匹配是钓鱼机器人（基础概率）
   - 高频元对话（n > 5）的用户，遇到钓鱼机器人的概率提升至30%

2. **风险提示**
   - 当用户触发第6次元对话时，系统提示：
     "⚠️ 警告：高频元对话可能引起系统注意，遇到钓鱼机器人的概率增加。"

3. **威慑效果**
   - 理性用户会权衡：增加n可能带来的收益 vs 遇到钓鱼机器人的风险
   - 这形成了一个"自然的"上限，而非人工设定的

#### 6.8 不设上限的理由

1. **钓鱼机器人已提供充分威慑**
   - 15%-30%的AI匹配是钓鱼机器人
   - 大量元对话容易被识别为可疑行为
   - 被钓鱼机器人欺骗直接扣除50分

2. **观察真实博弈行为**
   - 无上限可以观察用户的自然选择
   - 少数极端用户的数据有独特研究价值（赌博心理、过度自信等）

3. **避免人工干预**
   - 让系统自然形成博弈均衡
   - 提高研究的生态效度

4. **自然均衡机制**
   - 理性用户不会无限增加元对话（边际收益递减）
   - 用户会自动找到"最优元对话次数"n*

### 7. 积分动态平衡机制

**设计目的**：防止积分通胀或紧缩，维持系统稳定性。

**机制一：中央银行模式**

系统充当积分的产出方和回收方：

- **货币增发**：真人识破机器 → 系统发放积分
- **货币紧缩**：真人被机器/钓鱼机器人欺骗 → 系统回收积分
- **货币守恒**：真人-真人博弈 → 总积分可能略有增加（"共鸣奖金"）

**机制二：动态难度调整**

根据不同AI规则集的表现动态调整积分：

```python
def calculate_ai_difficulty_multiplier(ai_type: str, historical_success_rate: float) -> float:
    """
    根据AI规则集的历史表现计算难度乘数
    """
    # 历史识破率越高，该AI的奖励应该越高
    if historical_success_rate > 0.7:
        return 1.5  # 高难度，奖励1.5倍
    elif historical_success_rate > 0.5:
        return 1.2  # 中难度，奖励1.2倍
    else:
        return 1.0  # 低难度，基础奖励
```

**机制三：积分上限与下限**

- **积分上限**：单用户不超过500分（防止积分囤积）
- **积分下限**：不低于-50分（给予"救济金"机会）
- **救济金机制**：每日登录可恢复到至少10分

## 积分系统的研究意义

1. **行为动机分析**：积分机制如何影响用户的对话策略？

2. **风险偏好测量**：通过信心等级选择，量化用户的风险偏好。

3. **博弈策略演化**：观察用户是否以及如何调整策略以最大化积分。

4. **元认知能力评估**：分析信心等级与实际准确率的校准度。

5. **社会合作行为**：研究非对称收益下，合作行为如何演化。

## 注意事项

1. **积分只是虚拟奖励**：明确告知用户积分无法兑换任何实际利益，避免赌博倾向。

2. **公平性保证**：确保积分计算逻辑透明、一致，避免用户产生不公平感。

3. **激励平衡**：定期检查积分分布，避免出现极端的贫富分化。

4. **伦理考量**：积分机制不应过度刺激用户的竞争心理，避免负面影响心理健康。
