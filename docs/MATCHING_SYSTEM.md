## 🔄 匹配流程

### 阶段说明

后端采用**两阶段设计**：

```
阶段 1: 匹配完成 → session_id=0  → 结果存储
                │
                └──→ 异步创建会话（后台）
                      │
                      ▼
阶段 2: 会话创建 → session_id>0  → 可跳转聊天
```

### 前端状态流转

```
┌──────────────────────────────────────────────────────────┐
│                    前端匹配状态机                         │
│                                                          │
│   [Lobby] ──点击匹配──▶ [匹配中] ──15 秒超时──▶ [Lobby]   │
│                           │                              │
│                           ├─session_id>0──▶ [Chat]       │
│                           │                              │
│                           └─取消匹配──▶ [Lobby]          │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 后端状态流转

```
┌──────────────────────────────────────────────────────────┐
│                    后端匹配状态机                         │
│                                                          │
│   [加入队列] ──概率判定──┬──▶ [Bot 匹配] ──▶ [存储结果]    │
│                          │    (70%)       │              │
│                          │               ▼              │
│                          │         [异步创建会话]        │
│                          │                               │
│                          ├──▶ [真人匹配] ──8 秒超时─┐     │
│                          │    (70%)      └─有人 ────┘    │
│                          │               │               │
│                          │               ▼               │
│                          └──────────▶ [Bot 降级]         │
│                                          │               │
│                                          ▼               │
│                                     [异步创建会话]        │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

## ⏱️ 匹配时长分析

### 场景 1：Bot 匹配（70% 概率）

```
时序：
0.0s  前端：POST /api/match/join
0.1s  后端：概率判定 → Bot
0.2s  后端：分配 Bot (Lv1/Lv2/Lv3)
0.3s  后端：存储结果 (session_id=0)
0.4s  后端：返回结果 (session_id=0)
      前端：收到结果 (session_id=0) → 继续轮询
0.5s  后端：异步创建会话完成 (session_id=22)
1.0s  前端：轮询获取结果 (session_id=22) → 跳转聊天

总耗时：约 1-1.5 秒
```

### 场景 2：真人匹配 - 队列有人（最佳情况）

```
时序：
0.0s  前端：POST /api/match/join
0.1s  后端：队列有人 → 立即配对
0.2s  后端：存储结果 (session_id=0)
0.3s  后端：返回结果
      前端：收到结果 (session_id=0) → 继续轮询
0.5s  后端：异步创建会话完成 (session_id=20)
1.0s  前端：轮询获取结果 (session_id=20) → 跳转聊天

总耗时：约 1 秒
```

### 场景 3：真人匹配 - 队列无人后超时（最坏情况）

```
时序：
0.0s  前端：POST /api/match/join
0.1s  后端：队列无人 → 加入等待
      │
8.0s  后端：真人匹配超时
8.5s  后端：Bot 降级完成
8.6s  后端：返回结果 (session_id=0)
      前端：收到结果 (session_id=0) → 继续轮询
9.0s  后端：异步创建会话完成 (session_id=21)
9.5s  前端：轮询获取结果 (session_id=21) → 跳转聊天

总耗时：约 9-10 秒
```

### 场景 4：前端超时

```
时序：
0.0s  前端：POST /api/match/join
...   后端：处理中...
15.0s 前端：超时 → 离开队列 → 返回大厅

总耗时：15 秒（返回大厅，未进入聊天）
```

## 📊 时长总结

| 匹配类型 | 概率 | 直观匹配时长 | 说明 |
|---------|------|-------------|------|
| **Bot 匹配** | 30% | **~1-1.5 秒** | 立即分配 |
| **真人匹配（队列有人）** | 70% × P(有人) | **~1 秒** | 立即配对 |
| **真人匹配（队列无人→真人）** | 70% × P(8 秒内有人) | **1-9 秒** | 等待 + 配对 |
| **真人匹配（超时→Bot 降级）** | 70% × P(8 秒无人) | **~10 秒** | 超时降级 |
| **前端超时** | 极低 | **15 秒** | 返回大厅 |

## 🎯 真人匹配成功率分析

### 等待时长

用户在等待队列中的最大时长：**8 秒**（由 `timeout_seconds` 配置决定）

实际等待时长 = `min(下一位用户到达时间, 8 秒)`

### 成功率计算

假设：
- 用户到达率 = λ (人/秒)
- 等待窗口 = 8 秒
- 70% 用户选择真人匹配

在 8 秒窗口内，至少有 1 位真人到达的概率：
```
P(至少 1 人) = 1 - P(0 人) = 1 - e^(-λ×8×0.7)
```

### 实际数据

| 用户到达率 | 8 秒内真人匹配概率 | 能否匹配到 |
|-----------|------------------|-----------|
| 1 人/分钟 | 1 - e^(-0.05×8) ≈ 33% | ❌ 较低 |
| 5 人/分钟 | 1 - e^(-0.25×8) ≈ 86% | ✅ 较高 |
| 10 人/分钟 | 1 - e^(-0.5×8) ≈ 98% | ✅ 很高 |

**结论**：
- **低活跃度场景**（<5 人/分钟）：8 秒窗口可能不足以保证真人匹配
- **中高活跃度场景**（≥5 人/分钟）：8 秒窗口足够保证真人匹配

## 🔐 身份保密设计

```
后端存储（完整信息）          前端可见（脱敏）
┌────────────────────┐      ┌────────────────────┐
│ session_id: 19     │      │ session_id: 19     │
│ opponent_type: bot │      │ opponent_type:     │
│ true_identity:     │      │   "opponent"       │
│   "Bot_lv2_typical"│      │                    │
│ bot_level:         │      │                    │
│   "lv2_typical"    │      │                    │
│ is_honeypot: false │      │                    │
└────────────────────┘      └────────────────────┘
```

**设计原则**：前端永远无法得知对手的真实身份（真人/Bot/钓鱼）。

## 🛠️ 关键设计决策

### 1. 异步会话创建

**原因**：避免阻塞 API 响应，减少用户等待时间。

**实现**：
```python
# service.py::join_queue()
result = await self.coordinator.match_user(...)
# 异步创建会话（不阻塞）
asyncio.create_task(self._session_creator.create_session(result, user_id))
return result
```

### 2. 两阶段设计

**阶段 1**：匹配完成 → `session_id=0`（结果存储）
**阶段 2**：会话创建 → `session_id>0`（可跳转）

**前端适配**：
```typescript
// session_id=0 表示会话尚未创建完成，继续轮询
if (result?.session_id && result.session_id > 0) {
  navigateToChat()
}
```

### 3. 超时配置

| 配置 | 值 | 原因 |
|------|-----|------|
| 后端超时 | 8 秒 | 减少用户等待 |
| 前端超时 | 15 秒 | 确保收到响应（7 秒余量） |

### 4. 概率分流

```
100% 请求
├── 30% Bot 匹配
│   ├── 15% 钓鱼 Bot (4.5% 总请求)
│   └── 85% 普通 Bot (25.5% 总请求)
└── 70% 真人匹配
```
