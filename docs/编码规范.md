# Alice 项目编码规范

## 📋 概述

本文档定义了 Alice 项目中编码的标准规范，包括异常处理、优雅降级、代码风格等方面的要求，旨在提高代码质量、可维护性和系统稳定性。

## 🎯 设计原则

### 1. 明确性原则
- 异常信息应该清晰描述问题原因
- 避免使用模糊的错误信息
- 提供足够的上下文信息帮助调试

### 2. 分层处理原则
- 不同层级采用不同的异常处理策略
- 底层模块抛出具体异常，上层模块决定如何处理
- 避免在底层直接处理业务逻辑异常

### 3. 用户友好原则
- 对用户隐藏技术细节
- 提供有意义的错误提示
- 在适当时候提供恢复建议

### 4. 性能考虑原则
- 避免过度使用异常处理影响性能
- 合理使用条件检查替代异常
- 异常处理不应成为正常流程的一部分

## 🚨 优雅降级规范（重点章节）

### 1. 优雅降级的定义

**优雅降级**是指当系统遇到非致命错误时，能够自动切换到功能受限但仍可用的备用方案，同时：
- 保持核心功能的基本可用性
- 不影响用户体验的连贯性
- 提供清晰的状态指示
- 记录降级事件便于后续分析

### 2. 降级决策矩阵

| 错误类型 | 严重程度 | 是否允许降级 | 降级策略 | 用户提示 |
|---------|---------|-------------|----------|----------|
| 配置文件缺失 | 中等 | ✅ 可降级 | 使用内置默认配置 | "使用默认设置运行" |
| 外部API调用失败 | 中等 | ✅ 可降级 | 返回缓存数据/默认值 | "网络不稳定，显示缓存内容" |
| 可选功能模块缺失 | 低 | ✅ 可降级 | 跳过该功能 | "高级功能暂不可用" |
| 核心依赖库异常 | 高 | ❌ 不可降级 | 记录错误并终止 | "系统核心组件故障" |
| 数据库连接失败 | 高 | ❌ 不可降级 | 明确报错 | "数据库连接失败，请联系管理员" |
| 用户输入验证失败 | 低 | ❌ 不可降级 | 提示用户修正 | "请输入有效内容" |

### 3. 禁止降级的情况

以下情况**绝对不允许**进行降级处理：

```python
class APIClient:
    def __init__(self):
        self.cache = LRUCache(maxsize=1000)
        self.fallback_data = self._load_local_fallback_data()
    
    def get_user_profile(self, user_id: str) -> Dict:
        """获取用户资料"""
        # 首先尝试从缓存获取
        cached = self.cache.get(user_id)
        if cached:
            return cached
        
        try:
            # 尝试调用外部API
            profile = self._call_external_api(user_id)
            self.cache[user_id] = profile
            return profile
            
        except (NetworkError, TimeoutError, APIError) as e:
            logger.warning(f"外部API调用失败: {e}")
            self._record_degradation('api_call', str(e))
            
            # 降级到缓存数据
            if user_id in self.cache:
                logger.info("使用缓存数据")
                return self.cache[user_id]
            
            # 最后降级到本地备用数据
            fallback = self.fallback_data.get(user_id, {})
            if fallback:
                logger.info("使用本地备用数据")
                return fallback
            
            # 如果连备用数据都没有，则抛出明确的业务异常
            raise ServiceUnavailableError(
                "用户资料服务暂时不可用，请稍后再试"
            )

class FeatureManager:
    def __init__(self):
        self.features = {
            'advanced_nlp': self._check_advanced_nlp_available(),
            'realtime_analysis': self._check_realtime_analysis_available(),
            'personalization': self._check_personalization_available()
        }
    
    def _check_advanced_nlp_available(self) -> bool:
        """检查高级NLP功能是否可用"""
        try:
            # 检查必要的模型文件和依赖
            required_models = ['ltp_model', 'bert_model']
            for model in required_models:
                if not self._model_exists(model):
                    return False
            return True
        except Exception:
            return False
    
    def process_text_with_features(self, text: str) -> str:
        """根据可用功能处理文本"""
        processors = []
        
        # 根据功能开关选择处理器
        if self.features['advanced_nlp']:
            processors.append(self._advanced_nlp_processor)
        else:
            processors.append(self._basic_nlp_processor)
            logger.info("使用基础NLP处理（高级功能不可用）")
        
        if self.features['realtime_analysis']:
            processors.append(self._realtime_analyzer)
        else:
            logger.info("实时分析功能已禁用")
        
        # 顺序执行可用的处理器
        result = text
        for processor in processors:
            try:
                result = processor(result)
            except Exception as e:
                logger.error(f"处理器执行失败: {e}")
                # 这里不能降级，因为会影响结果准确性
                raise ProcessingError("文本处理失败") from e
        
        return result
```

### 5. 降级质量评估标准

#### 可接受的降级应该满足：

1. **功能完整性**：降级后仍能完成核心任务
2. **数据一致性**：不会产生错误或矛盾的结果
3. **用户体验**：用户能够理解当前状态
4. **可追溯性**：能够追踪降级原因和影响
5. **可恢复性**：系统能够恢复正常状态

#### 降级质量检查清单：

```python
class DegradationQualityChecker:
    """降级质量检查器"""
    
    def __init__(self):
        self.degradation_events = []
    
    def check_degradation_quality(
        self,
        original_functionality: str,
        degraded_functionality: str,
        impact_level: str,
        user_notification: str
    ) -> Dict[str, bool]:
        """
        检查降级质量
        
        Args:
            original_functionality: 原始功能描述
            degraded_functionality: 降级后功能描述  
            impact_level: 影响等级 ('low', 'medium', 'high')
            user_notification: 用户通知内容
            
        Returns:
            质量检查结果字典
        """
        checks = {
            '功能完整性': self._check_functionality_integrity(
                original_functionality, degraded_functionality
            ),
            '数据一致性': self._check_data_consistency(),
            '用户体验': self._check_user_experience(user_notification),
            '可追溯性': self._check_traceability(),
            '可恢复性': self._check_recoverability()
        }
        
        # 记录降级事件
        self.degradation_events.append({
            'timestamp': time.time(),
            'original_func': original_functionality,
            'degraded_func': degraded_functionality,
            'impact': impact_level,
            'quality_checks': checks,
            'passed': all(checks.values())
        })
        
        return checks
    
    def _check_functionality_integrity(self, original: str, degraded: str) -> bool:
        """检查功能完整性"""
        # 降级后的功能应该至少完成原始功能的核心部分
        essential_tasks = self._extract_essential_tasks(original)
        degraded_tasks = self._extract_essential_tasks(degraded)
        
        return set(essential_tasks).issubset(set(degraded_tasks))
    
    def _check_user_experience(self, notification: str) -> bool:
        """检查用户体验"""
        # 用户通知应该是清晰、有用的
        if not notification:
            return False
        
        # 不应该包含技术术语
        tech_terms = ['exception', 'null', 'undefined', 'stack trace']
        if any(term in notification.lower() for term in tech_terms):
            return False
        
        # 应该提供下一步建议
        return any(keyword in notification.lower() 
                  for keyword in ['请', '可以', '建议', '稍后'])

# 使用示例
checker = DegradationQualityChecker()

quality_report = checker.check_degradation_quality(
    original_functionality="基于LTP的深度句法分析",
    degraded_functionality="基于规则的基础句法分析", 
    impact_level="medium",
    user_notification="检测到网络不稳定，暂时使用简化分析模式"

if not quality_report['用户体验']:
```

### 6. 降级监控和告警

```python
class DegradationMonitor:
    """降级监控器"""
    
    def __init__(self):
        self.active_degradations = {}  # 当前激活的降级
        self.degradation_history = []  # 降级历史记录
        self.alert_thresholds = {
            'frequency': 10,      # 同一降级10次以上告警
            'duration': 300,      # 持续5分钟以上告警  
            'impact_severity': 3  # 影响严重度阈值
        }
    
    def register_degradation(
        self,
        component: str,
        reason: str,
        severity: int,
        recovery_plan: str = None
    ):
        """注册降级事件"""
        degradation_id = f"{component}_{int(time.time())}"
        
        degradation_info = {
            'id': degradation_id,
            'component': component,
            'reason': reason,
            'severity': severity,
            'start_time': time.time(),
            'recovery_plan': recovery_plan,
            'alert_sent': False
        }
        
        self.active_degradations[degradation_id] = degradation_info
        self.degradation_history.append(degradation_info)
        
        logger.warning(
            f"组件降级: {component} | 原因: {reason} | "
            f"严重度: {severity}/5 | 恢复计划: {recovery_plan}"
        )
        
        # 检查是否需要发送告警
        self._check_and_send_alerts(degradation_info)
    
    def resolve_degradation(self, degradation_id: str):
        """解决降级"""
        if degradation_id in self.active_degradations:
            degradation = self.active_degradations[degradation_id]
            degradation['end_time'] = time.time()
            degradation['duration'] = (
                degradation['end_time'] - degradation['start_time']
            )
            
            logger.info(
                f"降级已解决: {degradation['component']} "
                f"(持续时间: {degradation['duration']:.1f}秒)"
            )
            
            del self.active_degradations[degradation_id]
    
    def _check_and_send_alerts(self, degradation_info: Dict):
        """检查并发送告警"""
        # 频率检查
        component_degradations = [
            d for d in self.degradation_history
            if d['component'] == degradation_info['component']
            and time.time() - d['start_time'] < 3600  # 最近1小时内
        ]
        
        if len(component_degradations) >= self.alert_thresholds['frequency']:
            self._send_frequency_alert(degradation_info, len(component_degradations))
        
        # 严重度检查
        if degradation_info['severity'] >= self.alert_thresholds['impact_severity']:
            self._send_severity_alert(degradation_info)
    
    def get_degradation_report(self) -> Dict:
        """获取降级报告"""
        return {
            'active_degradations': len(self.active_degradations),
            'recent_degradations': len([
                d for d in self.degradation_history
                if time.time() - d['start_time'] < 86400  # 最近24小时
            ]),
            'most_degraded_components': self._get_most_degraded_components(),
            'average_recovery_time': self._calculate_average_recovery_time()
        }

# 全局降级监控器
degradation_monitor = DegradationMonitor()

# 在降级点使用
def risky_operation():
    try:
        return perform_complex_operation()
    except RecoverableError as e:
        # 注册降级而不是静默处理
        degradation_monitor.register_degradation(
            component='complex_operation',
            reason=str(e),
            severity=2,
            recovery_plan='将在下次系统维护时修复'
        )
        
        # 执行安全的降级操作
        return perform_safe_alternative()
```

```python
            "消息处理失败",
            extra={
                'user_id': user_id,
                'input': message[:100],  # 截断敏感信息
                'error_type': type(e).__name__,
                'error_message': str(e),
                'processing_time': time.time() - start_time,
                'success': False
            },
            exc_info=True
        )
        
        raise  # 重新抛出异常供上层处理
```

## ⚠️ 关键警告

**记住：优雅降级不是万能药！**

1. **核心功能绝不能降级**：输入验证、数据完整性检查、安全相关功能
2. **降级必须是临时的**：应该有明确的恢复机制和时间表
3. **用户必须知情**：适当的提示能让用户理解当前状态
4. **质量必须可控**：每次降级都应该经过质量评估
5. **记录必须完整**：便于问题追踪和系统改进

那些"随便降级"的做法往往会导致：
- 数据不一致
- 用户困惑
- 难以调试的问题
- 系统状态混乱
- 维护成本激增

**宁可明确报错，也不要随意降级！**

```python
class ExceptionMonitor:
    """异常监控器"""
    
    def __init__(self):
        self.exception_counts = defaultdict(int)
        self.last_exception_times = {}
    
    def record_exception(self, exception_type: Type[Exception], context: str = ""):

        key = f"{exception_type.__name__}:{context}"

        # 如果异常频率过高，发出告警

exception_monitor = ExceptionMonitor()
```

## 🔧 最佳实践总结

### 1. DOs（应该做的）
- ✅ 使用具体的异常类型而不是通用的 `Exception`
- ✅ 在异常信息中包含足够的上下文
- ✅ 记录异常日志以便调试
- ✅ 实现优雅降级而不是直接崩溃
- ✅ 为外部依赖提供超时和重试机制
- ✅ 编写异常处理的单元测试

### 2. DON'Ts（不应该做的）
- ❌ 吞掉异常而不记录或处理
- ❌ 使用过于宽泛的异常捕获
- ❌ 在异常信息中暴露敏感数据
- ❌ 让异常处理成为正常业务流程的一部分
- ❌ 忽略第三方库可能抛出的异常
- ❌ 在生产环境中显示技术性错误信息给用户

```python
import asyncio
import concurrent.futures

async def async_respond(self, user_input: str) -> str:
    """异步响应生成"""
```
