# 匹配机制设计

## 概述

本文档详细描述图灵测试实验平台的匹配机制设计。匹配机制是实验平台的核心组件之一，负责将用户与合适的对手（真人或 AI）进行匹配，确保实验的公平性和研究价值。

## 设计目标

### 核心目标

1. **消除时间线索**：确保匹配时间不能作为身份判断的线索
2. **真人优先**：优先匹配真人对手，保证真人 - 真人互动的机会
3. **用户体验**：提供良好的匹配体验，避免过长的等待时间
4. **研究纯净性**：确保匹配机制不影响用户判断行为

### 次要目标

1. **简单可维护**：实现简单，易于理解和维护
2. **可配置性**：参数可配置，便于调整和实验
3. **数据记录**：完整记录匹配过程，便于后期分析

## 匹配流程

### 整体流程

```
用户点击"开始匹配"
    ↓
加入匹配队列
    ↓
生成匹配延迟（统一分布）
    ↓
等待延迟时间
    ↓
延迟期间检查：是否有真人加入？
    ↓
    ├── 有真人 → 匹配真人 - 真人（80% 概率）
    │
    └── 无真人/概率未触发 → 匹配 AI
        ↓
    钓鱼机器人判断（15% 基础概率，高频元对话时 30%）
```

### 详细步骤

#### 步骤 1：加入队列

```python
async def join_queue(user_id: int, db: Session):
    # 记录开始时间
    self.waiting_queue.append(user_id)
    self.wait_start_time[user_id] = datetime.utcnow()
```

#### 步骤 2：生成延迟

```python
def _get_match_delay(self) -> float:
    """生成匹配延迟（真人 AI 使用相同分布）"""
    r = random.random()

    if r < 0.5:
        return random.uniform(0, 3)      # 50%: 0-3 秒
    elif r < 0.8:
        return random.uniform(3, 8)      # 30%: 3-8 秒
    elif r < 0.95:
        return random.uniform(8, 15)     # 15%: 8-15 秒
    else:
        return random.uniform(15, 30)     # 5%: 15-30 秒
```

#### 步骤 3：等待并检查

```python
# 等待延迟
await asyncio.sleep(match_delay)

# 检查期间是否有人加入
if len(self.waiting_queue) > 1:
    # 有人加入，匹配真人
    other_user_id = 找到队列中的其他人
    # 创建真人 - 真人会话...
else:
    # 仍然只有自己，匹配 AI
    # 创建 AI 会话...
```

## 时间分布设计

### 分布参数

| 时间区间 | 概率 | 累计概率 | 用户体验 |
|---------|------|---------|---------|
| 0-3 秒   | 50%  | 50%     | 快速匹配 |
| 3-8 秒   | 30%  | 80%     | 正常匹配 |
| 8-15 秒  | 15%  | 95%     | 稍慢 |
| 15-30 秒 | 5%   | 100%    | 较慢 |

### 设计理由

1. **50% 快速匹配（0-3 秒）**
   - 当队列中有人时，可以快速匹配
   - 提供流畅的用户体验
   - 对真人匹配和 AI 匹配都适用

2. **80% 在 8 秒内完成**
   - 大部分匹配在可接受时间内完成
   - 避免用户等待焦虑

3. **5% 较慢匹配（15-30 秒）**
   - 偶尔的长等待是正常的
   - 不会让用户产生"长等待=AI"的假设

4. **真人 AI 使用相同分布**
   - 关键设计：消除时间线索
   - 用户无法通过匹配时间判断对手类型

## 真人优先机制

### 优先策略（概率性）

```
1. 检查队列中是否有真人
   ├─ 有真人 → 80% 概率匹配真人 - 真人，20% 概率匹配 AI（实验对照）
   └─ 无真人 → 加入队列，等待延迟

2. 延迟期间检查
   ├─ 期间有人加入 → 80% 概率匹配真人 - 真人
   └─ 仍无真人 → 匹配 AI
```

### 实现细节

```python
# 优先匹配真人（概率性策略）
if self.waiting_queue:
    # 队列中有人
    if random.random() < self.human_priority_probability:  # 80% 概率
        other_user_id = self.waiting_queue.pop(0)

        # 生成延迟（真人真人都用）
        match_delay = self._get_match_delay()
        await asyncio.sleep(match_delay)

        # 创建真人会话
        session = SessionModel(
            opponent_type='human',
            opponent_id=other_user_id,
            match_duration=match_delay,
            ...
        )
    else:
        # 20% 概率：仍然匹配 AI（用于实验对照）
        # 创建 AI 会话
        ...

# 队列为空
else:
    # 加入队列
    self.waiting_queue.append(user_id)

    # 生成延迟
    match_delay = self._get_match_delay()
    await asyncio.sleep(match_delay)

    # 期间检查
    if len(self.waiting_queue) > 1:
        # 有人加入，80% 概率匹配真人
        ...
    else:
        # 匹配 AI
        session = SessionModel(
            opponent_type='ai',
            opponent_id=None,
            match_duration=match_delay,
            ...
        )
```

### 设计理由

保留 20% 的非真人优先匹配，用于研究用户对"错过真人匹配"的感知能力。这为实验提供了对照组，可以分析：
- 用户是否能感知到"本应是真人匹配"的场景
- 真人优先策略对用户判断行为的影响

## 钓鱼机器人机制

### 触发条件（动态概率）

- **基础概率**：AI 匹配时，15% 概率触发钓鱼机器人
- **动态调整**：高频元对话（n > 5）时，概率提升至 30%
- 钓鱼机器人的匹配时间分布与普通 AI 完全相同
- 用户无法通过匹配时间区分

> **✅ 已决议题 #3**：钓鱼机器人概率以 `project-docs/04-积分与博弈机制/钓鱼机器人机制.md` 和 `project-docs/04-积分与博弈机制/积分计算公式.md` 为准，包含动态概率调整机制。

### 钓鱼机器人类型

1. **互刷诱导型（60%）**
   - 第 2 轮主动提出互刷提议
   - 检测用户是否配合
   - 配合则扣 50 分

2. **身份暴露型（20%）**
   - 用户频繁询问身份时触发
   - 主动承认是真人（用机械方式）
   - 诱导用户放松警惕

3. **情感诱导型（20%）**
   - 用户情绪化时触发
   - 夸张的情感回应
   - 诱导用户进入情感陷阱

详细设计见：`project-docs/04-积分与博弈机制/钓鱼机器人机制.md`

## 数据库设计

### Session 模型

```python
class Session(Base):
    __tablename__ = "sessions"

    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, ForeignKey("users.id"))
    opponent_type = Column(String)  # 'human', 'ai', 'honeypot'
    opponent_id = Column(Integer, nullable=True)  # NULL if AI
    status = Column(String, default="matching")
    match_duration = Column(Integer, nullable=True)  # 匹配用时（秒）
    started_at = Column(DateTime, nullable=True)
    ended_at = Column(DateTime, nullable=True)
```

### 字段说明

- `match_duration`：记录实际匹配用时（秒）
  - 用于后期分析
  - 不显示给用户（只显示给用户看，不用于判断）
  - 真人匹配和 AI 匹配的分布相同

## 与其他机制的集成

### 与钓鱼机器人

- 钓鱼机器人匹配使用相同的时间分布
- 用户无法通过时间区分普通 AI 和钓鱼机器人
- 保持威慑效应
- 高频元对话用户（n > 5）遇到钓鱼机器人概率提升至 30%

### 与积分系统

- 匹配时间不影响积分计算
- 积分完全基于对话内容和判断结果
- 确保公平性

### 与元对话机制

- 元对话在匹配后才开始计数
- 匹配时间不影响元对话检测
- 保持机制独立

## 边界情况处理

### 情况 1：用户取消匹配

```python
def leave_queue(self, user_id: int):
    """用户离开匹配队列"""
    if user_id in self.waiting_queue:
        self.waiting_queue.remove(user_id)
    if user_id in self.wait_start_time:
        del self.wait_start_time[user_id]
```

if len(self.waiting_queue) > 1:

## 性能考虑

### 并发处理

- 使用 `asyncio.Lock` 保证线程安全
- 避免竞态条件
- 支持高并发匹配

### 内存使用

- 只保存必要的信息（user_id, start_time）
- 匹配完成后立即清理
- 避免内存泄漏

### 响应时间

- 匹配延迟主要在 `asyncio.sleep()`
- 不阻塞其他操作
- 异步处理保证性能
